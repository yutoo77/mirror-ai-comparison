# 公開の境界と確認手順

対象: v0.8.1 / 2026-09-07。公開先のURLと実際の公開状態は、ホスティング先・GitHub側で別途確認する。本書の存在は公開完了を意味しない。

## 含めるもの

現在の汎用アプリ、架空データ、テスト、設計資料、依存関係の固定ファイル。元の組織向けプロトタイプ、個人設定、APIキー、ブラウザの保存データは含めない。

`pnpm release:check` はGitの追跡対象と未追跡・非無視ファイルを読み、公開対象のルート、典型的な秘密情報、個人環境パス、文書のローカルリンクを点検する。一致した秘密の値はログに出さない。既存履歴、画像内の文字、権利関係、未知のトークン形式を完全に検査するものではない。

以前のローカルGit履歴には個人の作者メールが含まれるため、初回公開用のコピーでは、点検した現在のソースだけから新しい履歴を作る。元の作業フォルダ・履歴はそのまま保持する。公開コミットの作者は本人のGitHub noreplyアドレスを使う。

## 確認

1. `pnpm check`、`pnpm release:check` を実行する。公開点検スクリプトのテストも通常のテストに含まれる。
2. 公開用コピーには許可したソースだけを含め、`.git`、`.env`、`node_modules`、`dist`、一時ファイル、個人設定をコピーしない。初回は過去の履歴をpushしない。
3. ホスティングする場合は、本番ビルドの静的ファイルだけを配信する。APIキーをビルド変数へ入れない。ソースマップは出力しない。
4. SPAの各URLを直接開けるよう、ホスティング先で`index.html`へのフォールバックを設定する。HTTPSで配信する。
5. 公開先の実際のアクセス範囲・トップページ・深いURLを確認し、READMEへ実在するURLだけを記載する。

静的デモは外部AIを実行しない。実API接続は別の開発単位とし、公開デモから所有者のAPI予算を誰でも使える状態にしない。認証・上限・レート制限・秘密情報のサーバー側保管を整えてから有効にする。

公開リポジトリと公開アプリは別の配信先であり、片方の成功を両方の成功として扱わない。オープンソースの利用許諾を追加する場合は、所有者の選択を別途確認する。

## 2026-09-07の準備結果

- `pnpm check`: typecheck・ESLint・22ファイル174テスト・本番ビルドを通過。
- `pnpm release:check`: 現在の119候補ファイルで点検ルールの検出なし。これは秘密情報が絶対にないという保証ではない。
- `pnpm audit --prod`: 本番依存関係に既知の脆弱性の報告なし。開発依存関係と未知の脆弱性を含む保証ではない。
- 文書内の旧スクリーンショット6枚を目視し、架空デモであることを確認。現行画面の画像としては紹介しない。
- 以上は公開先を設定する前の検証結果。ソースとアプリURLの両方の公開について、同日に所有者の確認を得た。

検証中に見つかった、画面の遅延読み込みより先にWorkspace選択を探すテストは、画面が読み込まれるまで待つように修正した。テストの省略や判定条件の削除は行っていない。

## 公開先と更新

公開用コピーでも、22ファイル175テストを含む`pnpm check`と、120候補の`pnpm release:check`が通過した。元のソースとのファイル単位のSHA-256一致も確認した。追加した1テストは、公開する配信設定に秘密情報などの想定外フィールドを混ぜないための検証。

- アプリ: [Mirror](https://mirror-ai-comparison.seyuzau114yuto.chatgpt.site)
- ソース: [yutoo77/mirror-ai-comparison](https://github.com/yutoo77/mirror-ai-comparison)

初回の公開用コピーは元の作業フォルダ内の `.release/mirror-public` に分離する。古い履歴を持つ元フォルダから公開リモートへ直接pushしない。更新も、点検済みの現在のソースを公開用コピーへ反映して通常のコミットを追加する。公開済み履歴の強制書き換えはしない。

Sitesの識別情報とSPA設定は `.openai/hosting.json` に保存する。ここには秘密情報を入れない。別の人が独立してホストするときは、既存Siteの識別情報を流用せず、自分の配信先を設定する。静的配信のフォールバックで、比較・調査・資料・ヘルプのURLから直接開ける構成にしている。

GitHubの自動チェックはコードの検証用で、アプリを自動デプロイする設定ではない。アプリの更新時は、検証した同じソースをSites側にも保存・配信する。配信URLの準備・文書への記載と、公開配信の成功は別に確認する。
