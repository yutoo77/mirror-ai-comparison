# 原文の版管理と再確認

v0.8 / 2026-09-05。非公開のローカル実装。外部API・自動クロールは行わない。

## 使う流れ

1. 「公式情報」で確認項目の「原文を確認」、または資料タブの「原文と版履歴」を開く。
2. 「原文を更新」で新しい本文を貼り、文字差分を確認する。更新メモを入力して「新しい版を保存」。
3. 関連する確認済み項目は「要再確認」になる。対象・条件・時点を原文と照合し、必要に応じて確認項目の文章を直して保存する。
4. 「表示する版」から過去の原文を読む。関連する質問から比較ラボへ移動する。
5. 観測時の資料hashを持つ回答は、そのhashに一致する過去の原文を表示する。更新後の資料にも同じ判定が当てはまるとは扱わない。

原文更新は、関連する回答が誤っているという判定ではない。過去の人間レビューも自動取り消ししない。自動デモCampaignは、更新後の対象項目が未確認なら開始を拒否し、原文確認へ案内する。

## 保存と不変条件

- `Source.snapshot` が現在の保存版、任意の `Source.history` が古い順の過去版。旧データに履歴を捏造しない。
- 現在のSnapshotをそのまま履歴に複製してから、新しい本文・SHA-256・保存日時・手動記録方法・更新メモを保存する。
- 更新で既存のRun、Campaign、判定、Finding、レビューを編集しない。確認項目の文章を修正した後も、取得時の定義を持つRunには以前の文章が残る。
- 後からFindingを再集計しても、同じ観測に対応する保存原文を置き換えない。新しいFindingには取得時の対象と版を使う。版が見つからなければ本文は空、保存日時はnullとして、現在の原文や架空の日時で補完しない。
- Sourceの識別情報は内容の真偽・作成者・URLとの一致の証明ではない。同じhashに異なる本文が登録された場合は参照を拒否する。
- 原文10〜100,000文字、更新メモ1〜1,000文字、確認項目10〜2,000文字。過去版は50件まで。上限で停止し、古い版を勝手に削除しない。
- 変更のない原文や古い編集開始版による上書きを拒否。ハッシュ処理失敗では入力を保持する。原文編集中のEscapeや背景クリックでは、未保存入力の破棄を確認する。
- 非同期保存中にWorkspaceを切り替えても、別Workspaceへ更新を適用しない。複数タブ・複数端末間の競合解決は未実装。

## 比較とUIの限界

「文字の差分」は共通する先頭と末尾の間の変更範囲を示す。絵文字のサロゲートを分断しない。文章内に複数の独立変更がある場合、間の同じ部分も変更範囲に含む。意味の変化・矛盾・条件抽出を判定するアルゴリズムではない。

関連回答は、取得時の評価対象を優先して集計する。旧形式の回答は現在の質問設定を参考にする。関連数は誤り数でも、再確認を終えた数でもない。現在の確認項目の参照と過去の回答の参照が異なる場合、質問数と回答数は一対一に対応しない。

現時点ではタイトル・URL・記録者はSource単位。版ごとに保持するのは本文・保存日時・記録方法・hash・更新メモ。URLやタイトルを変更する編集機能はない。localStorage容量不足時は既存の警告とバックアップを使う。保存操作の成功表示だけでディスクへの永続化を保証しない。

## 持ち出し

版履歴または原文未収録のnull日時を含む書き出しは、`mirror.evidence-pack.v3` / `mirror.workspace-backup.v3`。それ以外は従来のv2を維持する。v1/v2への偽装ダウングレードを拒否し、過去版も外側のfingerprint検証の対象にする。履歴を含むバックアップの復元も、元のWorkspaceを置き換えない別コピー。

監査パックは5 MiB、バックアップは20 MiB。全文が大きいと、過去版50件より先にファイルやブラウザの容量制限へ達する。自動圧縮・削除・同期はない。暗号化や伏せ字も行わないので、共有前に原文と過去版まで確認する。

## 検証

2026-09-05、`pnpm check` 通過。typecheck、ESLint、21ファイル171テスト、production buildを確認した。

自動テストは、過去原文の保持・再起動相当の再読込・照合後の項目修正・未保存編集・保存失敗・無効な資料URL・検索なし結果・キーボードタブ・旧版からの比較・Finding再集計・未確認の新規Campaign拒否・v3書き出し/復元/改ざん/ダウングレード拒否を対象にする。

実画面はローカルのin-app Chromiumで1440×900、390×844、320×740を確認した。原文の閲覧・更新フォーム・文字差分・固定フッターを確認し、320pxの本文とダイアログに横はみ出しがないことをDOM寸法でも確認。Escapeで未保存編集の破棄確認へフォーカスが移り、「編集に戻る」で本文入力へ戻ること、入力が残ることを確かめた。確認用の未保存入力だけを破棄し、通常の比較画面へ戻した。

既存Workspaceを保護するため、実画面では新しい版の保存やレビューの確定を行っていない。保存・履歴・復元は隔離したテスト用ストレージで検証した。公開、実API呼び出し、保存データの初期化は行っていない。

実画面の確認と自動テストは、実ユーザーの有用性検証とは別。実API評価、クロスブラウザ、スクリーンリーダー、利用者の作業時間比較は未実施。
